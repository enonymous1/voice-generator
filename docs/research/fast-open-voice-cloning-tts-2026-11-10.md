# Fast, open zero-shot voice-cloning TTS — fourth-backend research

**Date read:** 2026-11-10. **Hardware / use in scope:** Windows, RTX 3060 12 GB VRAM, 64 GB RAM; English text scripts → WAV, offline; speed/throughput matter more than multilingual coverage. Baseline already owned (do not re-report as discoveries): Chatterbox Turbo (MIT), Qwen3-TTS 1.7B Base (Apache-2.0), CosyVoice 3 (Apache-2.0, hardest Windows install).

**How to read speed figures:** RTF = compute seconds ÷ audio seconds (RTF 0.3 ≈ 3.3× real-time; RTF 2.1 = slower than real-time). Some sources invert this as RTFx = audio ÷ compute (RTFx 3× = RTF 0.33). I state which form the source used. Almost all GPU figures are vendor claims on an RTX 4090/H100, **not** on an RTX 3060 — no reliable RTX 3060 figure was found for any candidate below. Do not extrapolate 4090 → 3060 linearly.

## Summary — answer first

**Recommendation: add VoxCPM2 as the fourth backend — the only candidate that is simultaneously (a) genuinely permissive for code *and* weights, (b) fast on a vendor-measured basis, (c) a one-line PyPI install, and (d) fits a 12 GB card at ~8 GB VRAM.** Confidence: moderate-high on licence/install/speed-claim; moderate on real-world RTX 3060 speed and English clone quality, which still need a local A/B against Chatterbox/Qwen3-TTS.

**Top 3 for this user:**
1. **VoxCPM2** — Apache-2.0, `pip install voxcpm`, RTF ~0.30 on RTX 4090 (~0.13 with Nano-vLLM), ~8 GB VRAM, 3–10 s clone, no transcript needed for basic cloning.
2. **GPT-SoVITS v2ProPlus** — MIT, fastest *vendor-published* RTF in this survey (0.028 on RTX 4060 Ti, 0.014 on RTX 4090), Windows integrated package (`go-webui.bat`), but it is a few-shot/WebUI toolkit, not a clean library backend; transcript required for the prompt.
3. **Pocket TTS (Kyutai)** — MIT code / CC-BY-4.0 weights (permissive, attribution only), 100M, ~6× real-time **on CPU**, ~200 ms first chunk, `pip install pocket-tts`; the CPU/off-GPU insurance policy, not the quality leader. Its cloning weights are HF-gated (accept-terms).

**Speed dark horse, not ranked in the top 3:** LuxTTS claims 150× real-time in 1 GB VRAM, but that claim is vendor-only, the project is a single-author repo (26 commits, Jan 2026), its ZipVoice lineage has an unresolved weights-licence problem, and — decisively for this user — tts-bench reports its install is **blocked on Windows (no Windows `piper-phonemize` wheel)**. Test it only as an experiment, not as the fourth backend.

**No other named candidate beats the three above on speed + licence + Windows.** OpenVoice V2 is cleanly MIT and genuinely fast in one independent bench, but its Windows install is old/fragile (Python 3.9, MeloTTS, PyAV). Zonos v0.1 is Apache-2.0 and ~2× real-time on a 4090, but officially Linux/macOS only. Everything else is either non-commercial, too slow, too big for 12 GB, dialogue-only, or not a zero-shot cloner at all (see per-candidate sections).

## Findings — one section per serious candidate

### 1. VoxCPM2 (OpenBMB) — RECOMMEND
- **Licence:** Apache-2.0 for weights and code, "free for commercial use" — stated twice on the model card / PyPI page. Verified live on PyPI, 2026-11-10. Source: https://pypi.org/project/voxcpm/ ; also https://huggingface.co/kkjipndy/VoxCPM2 (mirror; canonical is `openbmb/VoxCPM2`).
- **Speed:** Vendor table (RTX 4090, concurrency 1, `inference_timesteps=10`, `torch.compile` on): VoxCPM2 RTF ~0.30 standard, ~0.13 with Nano-vLLM; VRAM ~8 GB. Source: https://pypi.org/project/voxcpm/ (Models & Versions table). That is ~3.3× real-time standard, ~7.7× with Nano-vLLM — on a 4090. **No RTX 3060 figure found; expect materially slower, but the 8 GB footprint leaves headroom on a 12 GB card.** Streaming API exists (`generate_streaming`). No independent RTX 3060 bench found.
- **Windows install:** Easiest in this survey alongside Pocket TTS: `pip install voxcpm`; Python ≥3.10 (<3.13), PyTorch ≥2.5.0, CUDA ≥12.0. Source: https://pypi.org/project/voxcpm/ . Known Windows landmines (secondary, from docs summaries): Triton-on-Windows (`Python int too large…` — install `triton-windows`, match Triton to PyTorch, or pass `optimize=False` to skip `torch.compile`); `Could not load libtorchcodec` with reference audio (torchaudio ≥2.9 defaults to torchcodec — install system FFmpeg or force soundfile backend); `torch.compile` + background threads throws in `cudagraph_trees` (use `optimize=False` or Nano-vLLM). Source: https://localaimaster.com/blog/voxcpm2-apache-licence-voice-cloning . vLLM-Omni serving is Linux-oriented; do not plan on it for the Windows CLI — use the plain PyPI path, Nano-vLLM only if it proves Windows-clean.
- **Cloning:** Controllable cloning from a short reference clip, no transcript; "Ultimate Cloning" (clip + exact transcript) for maximum similarity; voice design from text description also available. 30 languages, 48 kHz out, accepts 16 kHz reference. Source: https://pypi.org/project/voxcpm/ . Secondary summaries put the short clip at 3–10 s. Source: https://www.solosoft.dev/post/voxcpm-tts-2026/
- **Quality/weaknesses:** Top-tier on Seed-TTS-eval / CV3-eval per vendor benchmarks (vendor-reported, not independently verified here); strong English zero-shot in those tables. Weaknesses: 2B model is the heaviest of the top 3; voice design is non-deterministic run-to-run; impersonation/fraud prohibition in README (does not affect licence).
- **Verdict:** Add first. Main risk: Windows Triton/torch.compile friction and unproven 3060 RTF — mitigate by shipping with `optimize=False` as fallback and benchmarking a 60 s script on the 3060 before committing.

### 2. GPT-SoVITS (RVC-Boss) — fastest measured, messiest to integrate
- **Licence:** MIT for the framework code (GitHub licence). Secondary licence surveys warn: "MIT (check base-model files)" / "fine-tuning base models and some dependencies carry their own license notes … model files and code must be checked separately." Source: https://aiwebcool.com/en/posts/opensource-tts-models-comparison-review . Treat as MIT-with-a-check, not blindly clean.
- **Speed:** The fastest vendor-published RTF in this survey, from the project README itself: v2ProPlus RTF **0.028 on RTX 4060 Ti, 0.014 on RTX 4090** (1,400 words ≈ 4 min audio in 3.36 s), 0.526 on M4 CPU. Source: https://raw.githubusercontent.com/RVC-Boss/GPT-SoVITS/main/README.md . Note the 4060 Ti figure is the most relevant to a 3060 (same class, newer) — still vendor-measured, single-model-version (v2ProPlus). A separate guide measured v4 inference RTF ~0.5 on RTX 5080 (Windows 11) — version matters enormously. Source: https://github.com/wty2003328/voice-cloning-guide/blob/HEAD/docs/models/gpt-sovits-v4.md
- **Windows install:** Best Windows story of the heavy models: integrated package, download and double-click `go-webui.bat` (tested Win ≥10); or Conda `python=3.10` + `pwsh -F install.ps1 --Device CU126|CU128|CPU --Source HF|HF-Mirror|ModelScope`, plus FFmpeg (`ffmpeg.exe`/`ffprobe.exe` in repo root). Tested envs: Python 3.10/3.11, PyTorch 2.5.1/CUDA 12.4, 2.7.0/CUDA 12.8. Source: https://raw.githubusercontent.com/RVC-Boss/GPT-SoVITS/main/README.md . No PyPI package; it is a WebUI/API toolkit, not a library — integrating into a CLI means driving its API/WebUI or vendoring its inference code, and its `requirements.txt` pins numpy/gradio/pydantic/peft ceilings that can collide with other backends (keep it in its own venv).
- **Cloning:** Zero-shot from 5 s of audio (per secondary summaries); its real strength is **few-shot fine-tuning** — ~1 min of data trains a voice model, LoRA ~30–60 min on an RTX 5080 for v4 (10 min data). That is *not* the user's workflow (3–10 s clip, no training). For pure zero-shot, the prompt needs audio **+ its transcript**. English quality is good but the ecosystem/quality tuning is Chinese-first; v3/v4 lean heavily on the reference clip and are less tolerant of average-quality training audio than v2/v2Pro. Source: https://github.com/wty2003328/voice-cloning-guide/blob/HEAD/docs/models/gpt-sovits-v4.md ; https://www.aiwindes.com/blog/gpt-sovits
- **Verdict:** #2. Worth adding only if the CLI can tolerate a separate venv + WebUI/API subprocess and the user accepts transcript-required prompting. Main risk: integration complexity and version maze (v1/v2/v3/v4/v2Pro/v2ProPlus are not a linear sequence).

### 3. Pocket TTS (Kyutai) — fastest on CPU, lightest, gated cloning
- **Licence:** Code MIT; weights **CC-BY-4.0** (permissive, commercial use allowed with attribution). Source: https://github.com/heimeshoff/utterheim/blob/HEAD/.agentheim/knowledge/research/kyutai-tts-2026-05-01.md ; https://github.com/kadirnar/voice-agent-next/blob/HEAD/docs/providers/pocket-tts.md . Caveat: individual preset voices have their own licences (two, `jean`/`cosette`, are CC-BY-NC-4.0 — irrelevant if you only use cloning, but check before bundling preset voices).
- **Speed:** Headline feature is CPU: **~6× real-time on a MacBook Air M4 using only 2 CPU cores, ~200 ms first-chunk latency**, 100M params, 24 kHz. Source: same Utterheim research note. Independent tts-bench (Windows Ryzen 9 9950X3D CPU, May 2026): TTFA warm 97–150 ms, **RTFx warm 2.9–3.0×** — the fastest cloning-capable option on that CPU rig. Source: https://github.com/5uck1ess/tts-bench/blob/HEAD/docs/results.md . GPU explicitly *not recommended* by Kyutai (no speedup). On the user's 64 GB RAM desktop CPU this will be fast; on GPU it wastes the 3060.
- **Windows install:** `pip install pocket-tts` (PyPI, version 2.0.0, 2026-04-21; `py3-none-any` wheel suggests Windows installs, but Kyutai docs only call out macOS numbers — Windows is not explicitly documented/tested by Kyutai). PyTorch ≥2.5 CPU build is fine. No espeak/pynini blocker found. Source: https://github.com/heimeshoff/utterheim/blob/HEAD/.agentheim/knowledge/research/kyutai-tts-2026-05-01.md
- **Cloning:** Sample-based zero-shot, no fine-tuning. Kyutai's own post says 5 s is enough; community write-ups quote ~20 s as a working number; other docs say 5–30 s, ideally clean. **Gated:** cloning weights (`kyutai/pocket-tts`) require accepting terms on Hugging Face and logging in; without access it silently falls back to `kyutai/pocket-tts-without-voice-cloning`. That gate breaks a fully-offline, no-account CLI flow on first run unless weights are pre-downloaded/cached. Source: https://github.com/kadirnar/voice-agent-next/blob/HEAD/docs/providers/pocket-tts.md ; https://github.com/calebhk98/phonetts/blob/HEAD/docs/research/pockettts-facts.md
- **Quality/weaknesses:** 6 languages (EN, FR, DE, PT, IT, ES — plus Dutch in one doc), 27 preset voices; no emotion controls, no speed parameter; max ~1,000 characters per request in one secondary summary (verify before long-form use); quality is good for its size but below Chatterbox/Qwen3-TTS class. English-only at launch per the May 2026 note, now 6 languages.
- **Verdict:** #3. Add as the CPU/off-GPU fallback, not as the primary speed backend. Main risk: HF accept-terms gate + quality ceiling.

### 4. LuxTTS (ZipVoice-based) — speed dark horse, do not make it the backend
- **Licence:** README (verified live): "The model and code are licensed under the Apache-2.0 license." Source: https://github.com/ysharma3501/LuxTTS . **But:** it is a distilled ZipVoice derivative, and ZipVoice's own weights carry **no licence grant at all** (no licence key in the HF card, none in the README frontmatter) and were trained on the CC-BY-NC-4.0 Emilia dataset. Sources: https://1btts.voicegateway.dev/ ; sherpa-onnx registry summary in search results. LuxTTS's Apache claim therefore does not settle the provenance question — flag for legal review before any commercial use.
- **Speed:** Vendor claim only: "150x realtime on a single GPU and faster then realtime on CPU's", 1 GB VRAM, 48 kHz, distilled to 4 steps. Source: https://github.com/ysharma3501/LuxTTS . **No independent benchmark found** (tts-bench lists it but could not install it — see below). Treat 150× as unverified marketing until measured on the 3060.
- **Windows install:** **Blocked.** tts-bench: "install blocked on Windows **and Apple Silicon** — no arm64/Windows `piper-phonemize` wheel". Source: https://github.com/5uck1ess/tts-bench/blob/HEAD/docs/results.md . Upstream install is `git clone + pip install -r requirements.txt`, HF `YatharthS/LuxTTS`, `device='cuda'/'cpu'`. Single-author repo, 26 commits, created 2026-01-23, 5,549 stars — thin maintenance.
- **Cloning:** ≥3 s reference (README: "Please use at minimum a 3 second audio file"). No transcript mentioned in the README example (`encode_prompt(prompt_audio)` only). EN + ZH only (ZipVoice lineage).
- **Verdict:** Experiment only. Main risk: Windows install blocker + licence provenance + unverified speed/quality.

### 5. OpenVoice V2 (MyShell / MIT)
- **Licence:** MIT for V1 and V2, code and weights — verified live on the repo: "Starting from April 2024, both V2 and V1 are released under MIT License. Free for commercial use." Source: https://github.com/myshell-ai/OpenVoice
- **Speed:** No vendor RTF on the README. Independent tts-bench (Mac M4): OpenVoice v2 **RTFx warm 5.91× on MPS, 2.49× on CPU**; TTFA warm ~1.0 s MPS / 2.4 s CPU — "fastest of the newly-added cloning models on MPS". Source: https://github.com/5uck1ess/tts-bench/blob/HEAD/docs/results.md . A laptop-CPU measurement found MeloTTS base synthesis very slow (RTF 6.46 incl. warm-up) with the OpenVoice conversion step at RTF 0.925 — i.e. the *base TTS* is the bottleneck on CPU, not the converter. Source: https://lucas.rangeltech.net/articles/voice-tts-stt-full-duplex-gpus/ . Secondary guides claim ~200 ms first-audio on RTX 4090 and 1–2 s/sentence on RTX 3070 — unverified. On a 3060 GPU it should be fast; no 3060 figure found.
- **Windows install:** The weak point. Requires MeloTTS as the base TTS (`pip install git+https://github.com/myshell-ai/MeloTTS.git` + `python -m unidic download`), Python **3.9 precisely** per secondary guides, Conda, CUDA GPU; PyAV Cython build failures on Windows are reported, with a community Windows guide/fork (`Alienpups/OpenVoice`, `docs/USAGE_WINDOWS.md`) and Docker suggested instead. The upstream package was renamed `openvoice` → `myshell-openvoice` (2025–26), breaking old pins (`Requested myshell-openvoice … has inconsistent name`). Sources: https://github.com/alsahuang0725/openclaw-alsahuang/blob/HEAD/skills/openvoice/SKILL.md ; https://vantaige.io/ai-tool/openvoice ; https://github.com/warith-harchaoui/sprezzature/blob/HEAD/sprezzature-publish/references/audio-narration.md
- **Cloning:** Instant, tone-colour cloning; reference length is inconsistently reported (1–5 s in one guide, 30 s in another survey — the README does not pin a number; verify empirically). No transcript required for the converter (MeloTTS synthesises the base voice; OpenVoice converts timbre). 6 native languages (EN/ES/FR/ZH/JP/KR); style/emotion/accent control is its differentiator. Quality is a generation behind Chatterbox/Qwen3-TTS/Fish — "slightly behind newer models" per surveys.
- **Verdict:** Cleanest licence in the survey after VoxCPM2, genuinely fast on GPU, but the Windows install is the most fragile of the permissive options and quality is dated. Reserve candidate if VoxCPM2's Triton issue proves worse in practice.

### 6. Zonos v0.1 (Zyphra) — Apache, fast, not native Windows
- **Licence:** Apache-2.0 — verified live. Source: https://github.com/Zyphra/Zonos
- **Speed:** Vendor README (verified live): "real-time factor of ~2x on an RTX 4090 (i.e. generates 2 seconds of audio per 1 second of compute time)"; Zyphra blog: TTFA 200–300 ms, RTF "significantly above 1" on RTX 4090. Source: https://github.com/Zyphra/Zonos ; https://www.zyphra.com/our-work/beta-release-of-zonos-v0-1 . 1.6B transformer or hybrid (Mamba2), 44 kHz native.
- **Windows install:** Officially **Linux (Ubuntu 22.04/24.04) / macOS only**; "For experimental windows support check out this fork." Source: https://github.com/Zyphra/Zonos . Windows path needs eSpeak-NG (Chocolatey/MSI + `PHONEMIZER_ESPEAK_LIBRARY=C:\Program Files\eSpeak NG\libespeak-ng.dll`), CUDA Toolkit, VS Build Tools for the hybrid compile step; community forks report flaky stability/artifacts. Install is `uv sync` / `pip install -e .` (+ `.[compile]` for hybrid). GPU 6 GB+ VRAM; hybrid additionally needs a 3000-series+ GPU (3060 qualifies). CPU is "a lot slower … likely won't be sufficient for interactive use."
- **Cloning:** README: 10–30 s speaker sample; Zyphra blog: 5–30 s. Speaker embedding *or* audio-prefix modes; no transcript required for embedding mode. Fine-grained speaking-rate / pitch / emotion conditioning.
- **Verdict:** Strong second-tier permissive option, but the Windows-via-fork status is a real maintenance risk for a CLI backend. Main risk: fork drift / no official Windows support.
- **ZONOS2 (successor, June 2026):** Apache-2.0, MoE 8B total / 900M active, "4× real-time throughput vs v0.1" (vendor), tts-bench warm RTFx ~2.0–2.1×, cold TTFA 2.5–8.3 s. But it ships **only as a Mini-SGLang server**, requires sm_80+ GPU kernels (flashinfer/sgl_kernel/cutlass — 3060 is sm_86 so it passes the floor, but the 8B total weights + server stack are unproven on 12 GB), and 41-language scope is irrelevant here. Not recommended for this user now. Sources: https://www.zyphra.com/our-work/zonos2 ; https://github.com/5uck1ess/tts-bench/blob/HEAD/docs/considered.md

### 7. Orpheus-TTS (Canopy Labs)
- **Licence:** Apache-2.0 on the fine-tuned card (`canopylabs/orpheus-3b-0.1-ft`), **but** it is a fine-tune of Meta Llama-3.2-3B-Instruct — secondary sources flag "read Meta's terms as well" and the card is gated. Source: https://www.yaps.ai/blog/best-local-tts-models
- **Speed:** Vendor: ~200 ms streaming latency, down to 25–50 ms with input streaming. Independent estimate: ~91 tok/s ≈ RTF ~1.0 (i.e. about real-time, not faster) on unspecified hardware; vLLM can serve 16–25 concurrent streams on H100. Source: https://github.com/vyvo-labs/vyvo-omni/blob/HEAD/docs/research/quality-tts-for-data.md . No RTF on a 3060 found. 3B model, ~8 GB VRAM (GGUF Q8 ~4 GB); the promised 1B/400M/150M smaller sizes were **not released as practical local models as of mid-2026** (treat as roadmap, not available).
- **Windows install:** Upstream `orpheus-speech` pip package depends on vLLM + CUDA PyTorch (Linux/CUDA path; vLLM pinned 0.7.3 after a regression). The practical Windows path is GGUF + llama.cpp/LM Studio + a community client (`isaiahbjork/orpheus-tts-local`) decoding SNAC tokens via `hubertsiuzdak/snac_24khz` — workable but indirect for a CLI. Source: https://codersera.com/blog/install-and-run-orpheus-3b-tts-on-macos-a-complete-guide/
- **Cloning:** Zero-shot from a short clip (5–10 s per guides; README recipe prepends the reference as a voice exemplar). Multiple sources agree cloning is **mediocre / "rough" / "weaker than fixed voices"**; its strength is the 8 built-in English voices + emotion tags (`<laugh>`, `<sigh>` …), not cloning fidelity. Source: https://github.com/vyvo-labs/vyvo-omni/blob/HEAD/docs/research/quality-tts-for-data.md ; https://www.yaps.ai/blog/best-local-tts-models
- **Verdict:** Do not add for cloning speed. English-only, ~real-time (not fast), cloning is its weak point.

### 8. Dia 1.6B / Dia2 (Nari Labs)
- **Licence:** Apache-2.0 (both). Source: https://theaitoolbible.com/tools/dia
- **Speed — too slow for this brief:** Dia 1.6B RTF ~2.1 (bf16 + compile) on RTX 4090 per vendor/community tables — i.e. **slower than real-time**; an independent Mac bench measured RTF ~4.4. Source: https://github.com/yepicaiaaron/awesome-audio-generation-2026/blob/HEAD/README.md ; https://tts.swaroop.se/ . Dia2 is streaming and community guides claim ~real-time / ~0.5× latency on CUDA, ~2.1× real-time on RTX 4090 in one provider doc — but those figures conflict and Dia2 is dialogue-oriented; no clean 3060 RTF found.
- **Windows install:** Dia via pip / Transformers (first-party HF integration now exists); Dia2 "CUDA strongly recommended", CPU/MPS essentially unusable (~840 s for 1.12 s audio on Apple CPU). No Windows-specific blocker found beyond CUDA-only practicality. Source: https://github.com/savg92/voice-cloning/blob/HEAD/docs/DIA2_GUIDE.md
- **Cloning:** Dia: 5–10 s clip **+ its transcript** (audio prompt). Dia2: prefix audio per speaker (Whisper-transcribed). Voices drift between runs unless seeded / prompted. **Dialogue-first:** `[S1]`/`[S2]` two-speaker generation, nonverbals (`(laughs)`…); single-speaker narration is "not its lane" — one bench found it truncated a 40 s passage to 19.6 s. Max ~2 min per generation (Dia2). English only.
- **Verdict:** Exclude for narration. Wrong shape (dialogue) and too slow.

### 9. Sesame CSM-1B
- **Licence:** Apache-2.0, gated HF download (+ Llama-3.2-1B access for the original repo). Source: https://www.reviewramble.com/models/csm-1b
- **Speed:** No vendor RTF/latency/VRAM figures published. Independent assessment: "impressive but **too slow for real-time. Even on H200 GPU, streaming latency is impractical**". Source: https://github.com/lacymorrow/juno/blob/HEAD/docs/audits/voice-model-research-2026.md . One engine catalog observed ~5 GiB VRAM, cold load ~196 s, 2.52 s infer for 1.52 s speech (i.e. slower than real-time on that run). Source: https://github.com/aivrar/portable-tts-server-V2/wiki/Engine-Catalog . 1B Llama backbone + Mimi codec, 24 kHz. No CPU-usable speed.
- **Windows install:** `pip install` the `csm` package / Transformers ≥4.52.1 native support; Python ≥3.10, CUDA GPU, ffmpeg. No Windows-specific blocker found, but the repo had **no commits since May 2025** (as of Nov 2026 review). Source: https://www.reviewramble.com/models/csm-1b
- **Cloning:** Context/segment conditioning, **not** a clean reference-clip API: supply reference audio **and its exact transcript** (10–15 s clean sample works well per a downstream doc); with no context it picks a random speaker. English only; other languages weak. Conversational prosody (pauses, breaths, chuckles) is its strength. Source: https://github.com/soniqo/speech-swift/blob/HEAD/docs/models/csm.md
- **Verdict:** Exclude for speed. Best-in-class conversational naturalness, worst-in-class latency in this survey.

### 10. Step-Audio (StepFun) — EditX and 2-mini
- **Licence:** Apache-2.0 (EditX repo + weights; Step-Audio 2-mini also Apache-2.0). Source: https://github.com/noonghunna/club-3090/blob/HEAD/docs/ai-studio/audio.md ; https://www.blog.brightcoding.dev/2025/09/20/step-audio-2-a-fully-open-source-model-for-speech-to-speech-conversation-and-deep-audio-understanding
- **Speed:** **No reliable RTF found for EditX.** It is the highest-ranked permissively-licensed model on the Aug 2026 Artificial Analysis board (Elo 1,102–1,109), but Elo is quality, not speed. One deployment reports "~30 s to load, then a clip in seconds" — not a benchmark. Step-Audio 2-mini (7B speech-to-speech) is a different, larger model — do not confuse it with EditX.
- **Windows install / fit — the blocker:** EditX README: 3B, **12 GB GPU optimal memory, "12GB is just a critical value, and 16GB GPU memory should be safer"**, tested on a single L40S, **tested OS: Linux**. AWQ 4-bit build ~8–10 GB (memory-efficient config ~6–8 GB with quality trade-off). Hard-pins `transformers==4.53.3` (4.54+ produces *silent audio* per authors) — a pin that will collide with other backends, so it needs its own isolated env/container. Source: https://huggingface.co/stepfun-ai/Step-Audio-EditX-AWQ-4bit ; https://github.com/noonghunna/club-3090/blob/HEAD/docs/ai-studio/audio.md
- **Cloning:** Zero-shot, 10–30 s reference **+ its transcript**; plus voice design / voice direction (emotion/style editing) — its real differentiator.
- **Verdict:** Exclude for this hardware/brief. Does not fit 12 GB comfortably, Linux-tested only, no speed evidence, pin conflicts. Revisit only if the user upgrades VRAM and wants editing, not speed.

### 11. MegaTTS 3 (ByteDance) — disqualified despite Apache
- **Licence:** Apache-2.0 for the repo (README: "This project is licensed under the Apache-2.0 License", "primarily intended for academic purposes"). Source: https://github.com/bytedance/megatts3/blob/HEAD/readme.md
- **Speed:** 0.45B diffusion-transformer backbone (~1.31B across 5 components); vendor note: "~30 s for 10 inference steps (vendor, hardware not named)" — slow, and no RTF published. Source: https://github.com/mahimairaja/awesome-open-tts-under-1b/blob/HEAD/README.md
- **The disqualifier:** ByteDance **withholds the WaveVAE encoder**, so a speaker latent cannot be built locally — "Voice cloning with your own audio is impossible" / "cloning a new speaker requires submitting a clip to ByteDance and waiting for a published latent". Source: https://opengauntlet.com/tts-legal.html ; https://github.com/mahimairaja/awesome-open-tts-under-1b/blob/HEAD/README.md . It can only synthesise from latents they provide.
- **Verdict:** Exclude. Not a usable zero-shot cloner for this CLI, regardless of licence.

### 12. FireRedTTS-2 / FireRedTTS3 (FireRed Team / Xiaohongshu)
- **Licence:** Apache-2.0 (both) — **but** both carry an "academic research purposes only" / "solely for academic research purposes" disclaimer for voice cloning in their READMEs. That disclaimer sits uneasily with Apache-2.0; treat as a yellow flag, not a clean green. Sources: https://pypi.org/project/tts-webui.fireredtts2/ ; https://github.com/saganaki22/fireredtts3-comfyui/blob/HEAD/README.md
- **Speed:** FireRedTTS-2: first-packet latency **140 ms on an L20 GPU** (vendor), streaming, 12.5 Hz tokenizer. No full-utterance RTF found. FireRedTTS3: no RTF found; one independent A/B found the *highest speaker similarity* of five engines (0.629) but the *least stable length* (6/11 takes ran past 15 s, worst 64 s). Source: https://github.com/chunjinsong000/claude-plugins/blob/HEAD/tts/skills/synthesize/SKILL.md
- **Size/fit:** FireRedTTS-2: 20.9 GB download, 9 GB VRAM in bf16. FireRedTTS3: 20 GB weights, 8–14 GB VRAM depending on variant/dtype. Both are tight-too-big for a 12 GB card shared with nothing else, and heavy to download. FireRedTTS3 **requires flash-attn** (hardcoded `flash_attention_2` in 3 places) — Windows-hostile. Source: https://firethering.com/open-source-tts-voice-cloning/ ; https://github.com/saganaki22/fireredtts3-comfyui/blob/HEAD/README.md
- **Cloning:** Zero-shot, 3–10 s (FireRedTTS-2, per speaker, up to 4 speakers / 3 min dialogue); FireRedTTS3 Base requires the reference **transcript**. Both are **dialogue/multi-speaker** systems first, single-speaker narration second.
- **Verdict:** Exclude for this brief (dialogue shape, size, flash-attn, research disclaimer, no RTF).

### 13. ChatTTS (2noise) — trap, and not a cloner
- **Licence:** **AGPL-3.0 code / CC-BY-NC-4.0 weights**, "for academic purposes only". Source: https://ghtrends.dev/2noise/ChatTTS/ ; https://www.edgechat.ai/chattts
- **Speed:** Developer-claimed RTF ~0.3 (secondary summary) — irrelevant given licence.
- **Cloning:** Does **not** clone an arbitrary voice; it samples a speaker (fix a seed for consistency). Deliberately degrades its own output (added high-frequency noise + MP3 compression as anti-misuse). Dialogue-oriented, ZH+EN.
- **Verdict:** Exclude on licence and on function.

### 14. Pheme (PolyAI)
- **Licence:** CC-BY (repo LICENSE) — permissive with attribution, but a 2024 model. Source: https://raw.githubusercontent.com/Pendrokar/open-tts-tracker/main/README.md
- **Speed:** **No reliable speed figure found.** Paper claims parallel non-autoregressive decoding / "true real-time synthesis" (2024), but no RTF, no VRAM, no 2026 bench was found. Do not assume it is fast on modern hardware.
- **Windows install:** No Windows install evidence found; old repo (arXiv 2401.02839), English only, one-shot prompting.
- **Verdict:** Exclude — outdated, thin evidence, no verified speed or Windows path. Not competitive with 2026 models.

### 15. Other credible candidates found (not in the original list)

**GLM-TTS (Zhipu AI, `zai-org/GLM-TTS`) — permissive, but CosyVoice-style Windows pain.**
Licence: Apache-2.0 code / MIT weights. Clone 3–10 s, no transcript stated; streaming, 400 ms first-frame latency (vendor site), 8 GB+ VRAM, ~9 GB weights, Python 3.10–3.12. CPU inference "5–15 minutes per generation vs seconds on GPU". **Windows blocker: requires a Conda hybrid env because of the `pynini` dependency, which is difficult to install via pip** — the same class of blocker as CosyVoice. One community bench measured 200%+ real-time on a GTX 3080 Ti (Linux). Sources: https://glm-tts.com/ ; https://github.com/thekk1/tts-audiobook-tool/blob/HEAD/README.md . Verdict: reserve; only if the user accepts a Conda env per backend.

**MOSS-TTS (OpenMOSS, Feb–May 2026) — emerging Apache family.**
Licence Apache-2.0 (weights + code). Local 1.7B ~5 GB VRAM ("only model fast enough for practical iterative use on a single consumer GPU" per ComfyUI node docs); Realtime 1.7B vendor TTFB ~180 ms, RTF 0.51; Nano 0.1B runs real-time on a 4-core CPU at 48 kHz stereo; flagship Delay 8B ~18 GB VRAM (exclude). Clone 3–10 s, **no transcript required**. 31 languages, hour-long generation claimed. Thin evidence: no clean pip/CLI install found (ComfyUI node, llama.cpp+ONNX, SGLang paths), no independent Windows bench, very new (v1.5 May 2026). Sources: https://howaiworks.ai/models/moss-tts/ ; https://runaihome.com/blog/moss-tts-comfyui-voice-cloning-2026/ ; https://andrew.ooo/posts/moss-tts-openmoss-family-voice-cloning-review/ . Verdict: watchlist — re-evaluate in a few months; not the fourth backend today.

**NeuTTS Air (Neuphonic) — Apache, GGUF, transcript-required.**
Licence Apache-2.0. 748M, ~3.26 GB VRAM measured on a 5090 (torch path), GGUF Q4 for llama.cpp. tts-bench: warm RTFx **1.62× on a 5090**, but **0.88–0.90× on Windows CPU** (below real-time) and 2.1× on M4 CPU; TTFA warm 0.67–0.70 s Windows CPU. Clone ~3 s **+ transcript** (wav + matching .txt, transcript must be literal). Sources: https://github.com/5uck1ess/tts-bench/blob/HEAD/docs/results.md ; https://github.com/pudaa/memoryservertts/blob/HEAD/docs/TTS_ENGINE_EVAL_2026.md . Verdict: decent fallback, beaten by Pocket TTS on CPU and by VoxCPM2 on GPU; transcript requirement is friction for the user's 3–10 s clips.

**OmniVoice (k2-fsa) — contested licence, do not adopt on headline alone.**
Headline: Apache-2.0, 600+ languages, vendor RTF 0.025 (40× real-time, H100), 3–10 s clone, `pip install omnivoice`, ~3.27 GB checkpoint. **But** tts-bench lists it as "Apache 2.0 code, **CC-BY-NC weights (non-commercial)**", and a licence assessment notes the bundled tokenizer is Higgs-Audio-2-derived under the **Boson Community License**. Sources: https://github.com/5uck1ess/tts-bench/blob/HEAD/docs/results.md ; https://github.com/hherb/primer/commit/b47bf89fc966fe082ff6c4594247c4e49d042df8 . Until the weights/tokenizer licences are resolved from the HF card itself, treat as non-commercial. Also: tts-bench's own GPU rig found it fast (cloning RTFx 9.2× on Mac), but that does not cure the licence. Verdict: exclude pending licence resolution.

**VibeVoice (Microsoft, 1.5B / Realtime-0.5B) — MIT, but slow and pulled.**
Licence MIT (code + weights per secondary sources), but Microsoft **pulled the official repo in Sept 2025** over misuse concerns; community fork preserves it. Realtime-0.5B: ~300 ms first chunk, 7 preset voices, **no cloning**; 1.5B clones but tts-bench CPU RTFx was **0.06×** (unusable on CPU; MPS OOMs at ~10.9 GiB) and no GPU RTF was found. Reference 30–60 s in guides (longer than the user's clips). Long-form/multi-speaker (up to 90 min, 4 speakers) is its niche, not fast narration. Sources: https://github.com/5uck1ess/tts-bench/blob/HEAD/docs/results.md ; https://getstream.io/blog/best-on-device-tts-models/ . Verdict: exclude for speed.

**Supertonic 3 — fast, but not a zero-shot cloner in the open repo.**
MIT code / **OpenRAIL-M weights** (use restrictions, incl. no impersonation without consent). 99M ONNX, RTF ~0.2–0.3 on CPU, 31 languages, `pip install supertonic`. The open repo has **no official voice-cloning pipeline** — cloning was via the hosted Voice Builder, which became inaccessible 2026-08-31, and the repo was announced for archiving July 2026. Source: https://ai-deck.app/blog/supertonic/ . Verdict: exclude as a cloner.

### 16. Not zero-shot cloners — excluded briefly (per brief §5)
- **StyleTTS 2:** MIT, excellent English narration, ~5–8× RT on RTX 4070 (secondary), 2–4 GB VRAM — but **generates in trained speaker voices only; voice cloning not supported**. Also depends on a GPL-licensed phonemizer; code unchanged since Aug 2024. Source: https://www.promptquorum.com/power-local-llm/local-tts-voice-cloning-piper-coqui-xtts
- **Kokoro-82M:** Apache-2.0, 82M, ~10× RT on CPU / ~96× on A10G, 54 preset voices — **no cloning**. (Its architecture derives from StyleTTS 2.)
- **Piper / MeloTTS / KittenTTS:** fixed-voice, fast, no cloning. Piper is now GPL-3.0 (archived MIT repo) per secondary sources — check before bundling.
- **ZipVoice (upstream, `k2-fsa/ZipVoice`):** 123M, Apache-2.0 *code*, **weights carry no licence grant** (see LuxTTS §4); ~123M, CPU RTF 1.22 at 4 NFE distilled (single-thread Xeon) per vendor, RTF 0.6–1.5 on M1 Pro per an independent bake-off — but the licence gap + transcript-must-match-prompt-exactly brittleness (a 6 s clip with a 28 s transcript repeats forever) make the upstream less attractive than its LuxTTS derivative, which inherits the same gap. Sources: https://1btts.voicegateway.dev/ ; https://dev.to/chongwang/three-bake-offs-to-find-a-voice-cloning-engine-that-runs-entirely-on-a-macbook-p8l

## Ranked shortlist (for THIS user: fast + genuinely open + Windows-friendly + good English zero-shot)

| Rank | Candidate | Why it ranks here | Main risk |
|---|---|---|---|
| 1 | **VoxCPM2** | Only one that clears all four bars at once: Apache-2.0, RTF 0.30/0.13 (4090), `pip install`, ~8 GB VRAM, no-transcript cloning, 48 kHz, streaming | Windows Triton/torch.compile; 3060 RTF unproven — benchmark before committing |
| 2 | **GPT-SoVITS v2ProPlus** | Fastest published RTF (0.014–0.028), MIT, Windows one-click package, 4060 Ti figure is closest to a 3060 | WebUI/toolkit integration, transcript-required prompt, version maze, base-model licence notes |
| 3 | **Pocket TTS** | Fastest on CPU (2.9–3.0× RTFx Windows CPU, ~200 ms first chunk), lightest (100M), `pip install`, MIT/CC-BY-4.0 | HF accept-terms gate for cloning weights; quality ceiling; ~1,000-char limit reported |

**Next in line:** OpenVoice V2 (clean MIT, fast on GPU, fragile Windows install) and Zonos v0.1 (Apache, ~2× RT, Linux-only officially) — either could displace #3 if Pocket TTS's gate is unacceptable, but neither displaces VoxCPM2.

## Final recommendation
**Add VoxCPM2.** It is the single clearest addition: permissive licence verified from the primary PyPI/model page, the fastest *credibly-packaged* GPU cloner that fits 12 GB, and the only top candidate with a one-line PyPI install that does not require Conda, a fork, a WebUI subprocess, or a gated download. Ship it in its own venv (Python 3.10–3.12, PyTorch ≥2.5, CUDA ≥12), default to `optimize=False` if Triton/torch.compile fails on Windows, pre-download `openbmb/VoxCPM2` weights once for offline use, and run a head-to-head on the RTX 3060 (same 3–10 s clip, same script, same chunking as Chatterbox Turbo) measuring wall-clock RTF and speaker similarity before making it the default fast path. Keep GPT-SoVITS v2ProPlus as the follow-up experiment only if VoxCPM2's 3060 speed disappoints — its raw RTF is higher, but its integration cost is an order of magnitude greater. Do **not** spend time on LuxTTS/OmniVoice/MegaTTS 3 until their licence/Windows blockers are resolved upstream.

## Could not verify / open questions
- **No RTX 3060 speed figure exists in public sources for any candidate** (all GPU RTFs are RTX 4090/4060 Ti/H100/L20 vendor claims, or Mac/CPU benches). Every speed ranking above is therefore conditional on a local 3060 measurement.
- **LuxTTS 150× claim:** vendor-only, no independent bench found; the 150× figure is not corroborated.
- **VoxCPM2 English clone quality vs Chatterbox/Qwen3-TTS:** vendor benchmark tables only; no independent blind listening comparison on the same English clips was found.
- **GPT-SoVITS base-model licences:** secondary sources flag per-file licence notes; the specific v2ProPlus checkpoint files were not re-read here.
- **OmniVoice weights licence:** sources conflict (Apache-2.0 headline vs CC-BY-NC per tts-bench; Higgs-derived tokenizer). The HF model card itself was not re-read in this run — resolve there before any use.
- **Pocket TTS 1,000-character limit and exact Windows behaviour:** secondary summaries only; Kyutai's docs emphasise macOS.
- **Dia2 / MOSS-TTS-Realtime / FireRedTTS3 RTF on a 3060:** no figures found; Dia2 figures conflict across sources.
- **Orpheus 1B/400M/150M models:** listed as planned in 2025 announcements; no evidence they shipped as practical local models by Nov 2026.
