How samples get here

After the A/B bench runs on the target Windows box, each backend’s WAV is converted to MP3 and dropped into site/samples/, with one entry per backend in samples.json. The page fills in automatically on the next deploy — no HTML edits.

:: 1. Run the bench (from the project folder, any Python)
python tools\ab_compare.py --script recording-script.txt --ref refs\me_10s.wav --ref-text-file refs\me_10s.txt --chatterbox-python .venv-chatterbox\Scripts\python.exe --qwen-python .venv-qwen3\Scripts\python.exe --voxcpm-python .venv-voxcpm\Scripts\python.exe --out-dir output\ab1

:: 2. Convert each WAV to MP3 (one per backend)
ffmpeg -i output\ab1\chatterbox.wav -codec:a libmp3lame -q:a 4 site\samples\chatterbox.mp3
ffmpeg -i output\ab1\qwen3.wav -codec:a libmp3lame -q:a 4 site\samples\qwen3.mp3
ffmpeg -i output\ab1\voxcpm.wav -codec:a libmp3lame -q:a 4 site\samples\voxcpm.mp3

:: 3. Add one entry per backend to samples.json, e.g.
:: {"backend": "voxcpm", "file": "samples/voxcpm.mp3",
::  "duration_s": 52.3, "wall_s": 18.4, "sample_rate": 48000}
:: (duration_s and wall_s come from output\ab1\ab_comparison.json)

:: 4. Commit + push — the Pages workflow redeploys the site

The raw reference clip (refs/me.wav) is never published — it is personal data and gitignored for that reason. Only the rendered clones go on this page, and only because a voice-clone demo is the point of the page.
